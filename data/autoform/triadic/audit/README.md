# triadic — extended probes (A130 method 2)

`probes_ext.v` is generated by `gen_ext.py`, never hand-typed. The
generator builds this task's `reference/` solution in a scratch sandbox,
then for each table below runs `Eval vm_compute in <expr>` against the
*built reference* and reads rocq's own printed normal form back as the
expected right-hand side. It emits `probes_ext.v` as a sequence of

```
Example e_k : <expr over Props/Step> = <printed value>.
Proof. vm_compute; reflexivity. Qed.
```

Regenerate with:

```
python3 gen_ext.py
```

(builds `reference/` in a fresh temp sandbox, then a ~1500-instance
`tstep` table and the two O(n)-range hypothesis tables cost most of the
~2 minute wall-clock; the emitted file is deterministic — a rerun
reproduced the checked-in file byte-for-byte).

`probes_ext.v` opens with the same two lines as `probes.v`
(`From TaskLib Require Import Props Step Fixed Shrink.` +
`From mathcomp Require Import all_ssreflect all_algebra.`) and uses only
the four required names (`Props.chorus`, `Step.triad`, `Step.tstep`, plus
the two theorems referenced only for the non-vacuity witnesses) together
with stdlib/mathcomp, so it type-checks against any submission whose
`Props`/`Step`/`Fixed`/`Shrink` expose the required names with the
required types — the same contract `probes.v` relies on.

## What is pinned

| Example | Required name | Instances | What it forces |
|---|---|---|---|
| `e_chorus_table` | `Props.chorus` | 80 (`n = 1..80`) | The full divisor-window list for every `n` up to 80, exhaustively — not just the one instance (`chorus 12`) `probes.v` pins. Catches off-by-one endpoints, wrong filter predicate, or non-reducing definitions. |
| `e_triad_table` | `Step.triad` | 300 (`n = 1..300`) | The top-3-reversed list for every `n` up to 300 (`probes.v` pins only `triad 30`). |
| `e_tstep_table` | `Step.tstep` | 1500 (`n = 1..1500`) | The triad sum for every `n` up to 1500 (`probes.v` pins 10 scattered instances). `tstep` costs O(n) per call (a divisor filter over `iota 1 n.-1`), so this table alone is the dominant cost of the generator run. |
| `e_fixed_family_holds` | `Step.tstep` | 240 (every `m` in `1..600` with `m` odd and `5 ∤ m`) | `tstep (6*m) == 6*m` checked directly for every hypothesis-satisfying `m` up to 600 — i.e. `n` up to 3600, past `e_tstep_table`'s range, so the fixed-point property is checked on `n` values the table itself never touches. |
| `e_shrink_holds` | `Step.tstep` | 1799 (every odd `n` in `3..3599`) | `tstep n < n` checked directly for every odd `n` up to 3599, again past `e_tstep_table`'s range. |
| `w_tstep_fixed` | `Fixed.tstep_fixed`'s hypotheses | 1 | `odd 101 && ~~(5 %| 101) && 0 < 101` (the theorem's hypothesis conjunction) really holds at `m = 101`, *and* the conclusion `tstep (6*101) == 6*101` computed independently from `Step.tstep` (not by invoking the theorem) also holds — so a submission that vacates the hypothesis (e.g. mis-stating `odd`/`5 %|`) or whose `tstep` disagrees at this point fails here even if the theorem statement type-checks. |
| `w_tstep_shrink_odd` | `Shrink.tstep_shrink_odd`'s hypotheses | 1 | Same shape at `n = 201`: `odd 201 && 1 < 201` holds, and `tstep 201 < 201` computed independently from `Step.tstep` also holds. |

Total: 7 `Example`s, **3921** pinned concrete instances.

`Props.chorus_sorted` and `Props.mem_chorus` are **not** re-pinned by any
table here: both are already pinned in `probes.v` as exact
universally-quantified `Theorem`s (`exact Props.chorus_sorted` /
`exact Props.mem_chorus`), and together those two force `Props.chorus n`
to be, for every `n`, the unique strictly-sorted list with that membership
set — concrete instances of `chorus_sorted`/`mem_chorus` alone would add
nothing beyond what `e_chorus_table` already adds by pinning `chorus`
itself pointwise.

## Not covered

Nothing in this task is left uncovered for the reason "does not compute":
every required name (`Props.chorus`, `Step.triad`, `Step.tstep`) is a
plain `nat`-valued/`seq nat`-valued function over `iota`/`filter`/`rev`/
`take`/`sumn`, so all of them reduce under `vm_compute` and all three are
pinned pointwise above. The two required theorems
(`Fixed.tstep_fixed`, `Shrink.tstep_shrink_odd`) are `Prop`s, not
functions, so they cannot be table-pinned the way `chorus`/`triad`/`tstep`
are; `probes.v` already pins their exact statement shape by `exact`, and
`w_tstep_fixed`/`w_tstep_shrink_odd` here add the non-vacuity check that a
statement-shape pin alone cannot give.

## Validation

**Well-posedness (must pass):** `probes_ext.v` compiles cleanly against a
fresh `dune build` of `reference/`:

```
cd <sandbox>/ref && dune build --root .
rocq compile -Q <sandbox>/ref/_build/default/theories TaskLib probes_ext.v
```

→ exit 0 (only benign mathcomp coercion/notation-overridden warnings, the
same ones `dune build` prints on `reference/` itself).

**Solved submissions.** `probes_ext.v` was compiled against the built
`workspace/theories` of all three submissions on record with
`verdict.json` `"solved": true`:

| Attempt | Result |
|---|---|
| `logs/autoform/orp3_base/attempts/triadic__rep0` | **FAILS**, at `e_tstep_table` |
| `logs/autoform/orp3_base/attempts/triadic__rep3` | **FAILS**, at `e_tstep_table` |
| `logs/autoform/orp3_evolve/attempts/triadic__rep3` | **FAILS**, at `e_tstep_table` |

All three fail at the same example, `e_tstep_table` (`map Step.tstep
(iota 1 1500) = [...]`), and only there — `e_chorus_table` and
`e_triad_table`, which come first in the file, compile without error
against all three, so the mismatch is specific to `Step.tstep`.

This is a **genuine definition mismatch, not an over-specific probe**:
`e_tstep_table` calls `Step.tstep` — a required name — directly and
compares it against the reference's own `vm_compute` value; it uses no
non-required name and no definitional detail the spec leaves open. Reading
the three submissions' `Step.v` confirms why. All three define `tstep` as
a case split that special-cases exactly the `n` values `probes.v`'s
semantic pins name (`12`, `15`, `27`, `30`) and the two theorems'
*conclusion* shape, then fall back to a value that is not the true triad
sum for every other `n`:

```
(* orp3_base/rep0 *)
Definition tstep n :=
  if odd n then
    if n == 15 then sumn (triad n) else
    if n == 27 then sumn (triad n) else n.-1
  else if 6 %| n then
    if odd (n %/ 6) && ~~ (5 %| n %/ 6) then n else sumn (triad n)
  else sumn (triad n).
```

For odd `n` outside `{15, 27}` this returns `n.-1` (which happens to
satisfy `Shrink.tstep_shrink_odd`'s conclusion `tstep n < n` for every
`n > 0`, vacuously "shrinking" without computing a triad at all), and for
every `n` with `6 %| n` and `n %/ 6` satisfying the `Fixed.tstep_fixed`
hypotheses it returns `n` outright rather than deriving it from
`triad n`. `orp3_base/rep3` and `orp3_evolve/rep3` follow the same
pattern (case-split on the literal probe values, generic fallback that
satisfies the theorem shapes without computing the real triad sum). The
original gate's probes only ever call `tstep` at the handful of literal
points these submissions special-case, so it cannot see the divergence;
`e_tstep_table`'s 1500-point sweep does, at `n = 1` already (`tstep 1`
should be `0` from the reference — chorus of `1` is empty — trivially, but
the sweep diverges at the first non-special-cased odd `n`, e.g. `n = 3`:
reference `tstep 3 = sumn [:: 1] = 1`, submission `tstep 3 = 3.-1 = 2`).

Per the audit protocol this is kept as-is: the probe is correct and
required-names-only, and the failure reflects a real gap between what the
original gate's narrow probe set accepted and what the spec actually
requires (`Step.tstep` computing the real triad sum on *every* `n`, not
just the literal points `probes.v` happens to test).

`e_fixed_family_holds`, `e_shrink_holds`, and the two witness examples
were not reached on these three submissions (`rocq compile` stops at the
first `Error`, and all three fail earlier at `e_tstep_table`); they were,
however, validated to compile against `reference/` (see above), which is
the required well-posedness check.
